# 技术报告：小数据 + 严格延迟约束下的胸片多标签分类

> 本文记录一个完整方案的**推导过程与实测结论**，重点不在最终分数，而在
> 「哪些手段在 30k 图规模 + 100 ms/study 约束下真正有效」。

---

## 1. 问题设定

| 项 | 内容 |
|---|---|
| 任务 | 胸片 10 类多标签分类（9 类计分，第 10 类 No Finding 不计入主指标） |
| 评估 | study 级宏平均 AUC |
| 数据 | 30,344 图 / 18,513 study（训练），1,422 图 / 859 study（验证），2,218 图 / 1,414 study（测试） |
| **延迟约束** | **≤100 ms/study**（端到端，含读图、预处理、前向、后处理） |
| **体积约束** | **≤500 MB**（推理时实际加载的权重） |

三条约束叠加后，可用手段被大幅压缩：**你最多只能放两个 896 分辨率的模型**。

---

## 2. 最终方案

```
输入 896×896 灰度（复制 3 通道，ImageNet 归一化）
  ↓
ConvNeXt-Small@896（24 轮）  ┐
                             ├→ logit 平均 → sigmoid → 患者平滑 → 输出
ConvNeXt-Tiny @896（12 轮）  ┘
```

### 2.1 为什么要两个模型而不是一个更大的

| 方案 | val（9 类 AUC）| 延迟 | 体积 |
|---|---:|---:|---:|
| S@896 单模型 | 0.8112 | 55 ms | 189 MB |
| **S@896 + T@896** | **0.8134** | **66 ms** | **295 MB** |
| B@896 单模型（88M） | 0.8020 | 88 ms | 334 MB |
| 3 × 896 | 0.8141 | 83 ms | 485 MB |
| S@1024 单模型 | 0.8116 | 60 ms | 189 MB |

**结论**：在 100 ms 预算内，**「两个中等模型」优于「一个大模型」**；
再加第三个模型会挤到 83 ms，余量不足以应对跨硬件差异（评测机比开发机慢约 30%）。

### 2.2 延迟优化的关键：把预处理搬到 GPU

最初实现是「CPU 解码 + `cv2.resize` + CPU 归一化」，在 8 核 Xeon 上实测：

| 阶段 | 耗时（慢 CPU）|
|---|---:|
| `cv2.imdecode`（1/2 降采样） | 40.9 ms/图 |
| `cv2.resize` 到 896 | 19.2 ms/图 |
| fp16 前向 | 11.9 ms/图 |
| **每 study（1.8 图）** | **102.6 ms** ❌ |

改造成全 GPU 后：

| 阶段 | 耗时 |
|---|---:|
| nvJPEG 解码（`torchvision.io.decode_jpeg(device="cuda")`）| 51.7 ms/study |
| GPU 双线性 + antialias 缩放 + 归一化 | ~2 ms |
| 两次 fp16 前向 | ~25 ms |
| **每 study** | **~66 ms** ✅ |

**关键点**：`F.interpolate(antialias=True)` 在 GPU 上只需 0.1 ms，
而同样的缩放用 `cv2.resize(INTER_AREA)` 在慢 CPU 上要 19 ms/图。
**把可以并行的逐元素运算搬到 GPU，是这个方案能落地的直接原因。**

### 2.3 精度选择：FP16 而非 BF16

评测硬件是 T4（Turing，sm_75），**不支持 bf16 的 tensor core**，
`autocast(bfloat16)` 会退化为 fp32 计算。实测 fp16 与 bf16 在 Ada 上等价
（40.10 vs 39.95 ms），但在 T4 上 fp16 有原生加速。

> 教训：**精度选择要看目标硬件**，不能只看开发机上的 benchmark。

### 2.4 患者级后处理

同一患者的多次检查共享解剖结构，疾病有无往往连续。因此对同一 Subject 的
多个 study 做确定性混合：

```
p'_s = (1-λ)·p_s + λ·mean(同一 Subject 除 s 外其他 study 的 p)
λ = 0.15（在验证集上选定后冻结）
单 study 患者：λ = 0（退化为不平滑）
```

**实现细节**：均值必须**不含自身**。早期实现把自身算进均值，等价于把 λ 削弱
为 `λ·(n-1)/n`（n=10 时 0.15→0.136），与公式不符。

**收益与患者结构强相关**（验证集实测）：

| 患者 study 数 | 平滑增益 |
|---|---:|
| 1 | 0 |
| 2–4 | −0.0004 |
| 5–9 | +0.0013 |
| ≥10 | **+0.0041** |

测试集平均 10.4 study/患者（验证集只有 3.8），所以平滑在测试集上的收益远大于验证集。

## 3. 被证伪的方向

以下都做过受控实验（单变量），结论全部为**无增益或负增益**。

### 3.1 预训练与骨干

| 实验 | val | 对照 |
|---|---:|---:|
| RAD-DINO 冻结特征 + 线性探针 | 0.7699 | S@896 0.8120 |
| RAD-DINO + LoRA | 0.7217 | 同上 |
| BiomedCLIP 全量微调 | 0.7400 | 同上 |
| torchxrayvision DenseNet121 | 0.685 | 同上 |
| ImageNet-22k 预训练 | 0.8008 | in12k 0.8095 |
| DINOv3（16.89 亿张 SSL）| 0.8113 | in12k 0.8120 |
| ConvNeXt-Base@896（88M）| 0.8020 | S@896 0.8120 |

**解读**：医学预训练在这个数据规模上反而更差。做过一次数据量扫描
（固定一切，只变初始化与数据量）发现：**域先验的收益随数据量对数线性衰减**，
在约 1.2 万 study 处归零——本任务 1.85 万 study 已越过该点。

### 3.2 训练策略

| 实验 | val | 对照 |
|---|---:|---:|
| 30 轮 @768 | 0.8061 | 12 轮 0.8086 |
| T@896 24 轮 | 0.8060 | 12 轮 0.8111 |
| S@896 36 轮 | 0.8121 | 24 轮 0.8134 |
| Mixup / 过采样 / model soup / EMA | 均无增益 | — |

**重要发现**：**加长训练对大模型有益、对小模型有害**。
S（49M）12→24 轮 +0.0014；T（28M）12→24 轮 −0.0051。小模型更快过拟合。

### 3.3 蒸馏

做过 4 代蒸馏实验，**全部无增益甚至负增益**：

| 教师 | 学生 | 结果 |
|---|---|---:|
| 9 模型集成（768/512）| T@768 | 持平 |
| 3×896 集成 | S@768 | −0.002 |
| 3×896 集成 | S@896 | −0.001 |
| 24 轮版教师 | S@896（24 轮）| **−0.0023** |

**结论**：在本任务上，教师变强 → 学生变差。软标签让模型偏离对真实标签的直接优化，
而 30k 数据不足以弥补这一偏离。

### 3.4 集成

| 组合 | val | 延迟 |
|---|---:|---:|
| 2 × 896 | 0.8134 | 66 ms |
| 3 × 896 | 0.8133 | 81 ms |
| 4 × 896 | 0.8131 | 95 ms |
| S@896 + T@896 + S@768 | 0.8137 | 83 ms |
| S@896 + DINOv3@896 | 0.8122 | 66 ms |

**同分辨率集成在 2 个成员处饱和**；跨分辨率（896 + 768）能小幅提升，
但第三个成员会把延迟推到 83 ms，超出安全余量。

### 3.5 后处理

| 实验 | 结果 |
|---|---|
| 每类独立 λ（9 个自由参数）| 全量拟合 +0.0019，**分半交叉验证仅 +0.0001**（过拟合） |
| 学习式聚合（4 特征 → 小 MLP 预测 λ）| 上界 0.8129 < 固定 λ 的 0.8138 |
| TTA（3 尺度 × 翻转）| 0.8152 < 无 TTA 0.8167 |

**TTA 为什么反而更差**：训练已用强增强（RandAugment + RandomResizedCrop + 旋转），
模型对尺度/翻转已鲁棒；TTA 的 3 个尺度里有两个偏离训练分布，引入噪声。

## 4. 工程实现要点

### 4.1 图像缓存

训练时每次解码 2,218×1,797 的 JPEG 要 ~40 ms，是数据管线的瓶颈。
预先把全部图片解码并缩放成 `uint8` 的 memmap 数组（896 分辨率约 23 GB），
训练时随机索引即可：

```bash
python tools/build_cache.py --size 896 --splits train valid --workers 10
```

### 4.2 端到端计时脚本

`cost.py` 严格按赛事要求实现：

* 位置参数 `submission.csv pictures_100 pictures_5`
* 只做计时与一致性校验，**不产生任何文件**
* 复用 `code/predict.py` 的模型加载与推理函数（同一套代码）
* 输出固定格式的 `[CONCLUSION]` 行

一致性比对口径：概率保留 **4 位小数**，逐 study 比对二值判定与排序。

### 4.3 踩过的坑

| 现象 | 根因 | 修正 |
|---|---|---|
| 云端测出 110 ms（以为超时）| 测时 GPU 正在跑训练 | 空闲复测 56 ms |
| 本地测出 108 ms（不可信）| 桌面壁纸程序占用 GPU | 只用空闲机器的数据 |
| 一致性差 0.057 | 平滑把自身算进均值 | 改为「其他 study 均值」 |
| 训练数据量突然变成 77k | 环境变量 `CXR_DATA_DIR` 被其他实验设置 | 启动前 `env -u` |
| `import code.xxx` 失败 | `code` 与 Python 标准库同名 | 用 `importlib.util.spec_from_file_location` |

---

## 5. 结论

1. **数据量决定天花板**：30k 图规模上，单模型 val 在 0.81 附近，任何骨干/预训练
   的替换都难突破 ±0.01。
2. **延迟约束决定可用手段**：100 ms 只能放 2 个 896 模型，集成上限被锁死。
3. **真实有效的三个杠杆**：分辨率（768→896）、集成（1→2 模型）、患者级后处理。
4. **域先验的收益随数据量衰减**：医学预训练在 1.2 万 study 以上不再有优势。
5. **加长训练要看模型容量**：小模型加长会过拟合。

如果重做一次，会把这些资源集中在：**更早确定「两模型 + 896」的架构**，
把时间花在数据质量与增强策略上，而不是反复更换骨干。
